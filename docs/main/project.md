## 🗄️ Система контроля миграции MS SQL → PostgreSQL

### 📋 Обзор системы

Система контроля миграции реализована в схеме `mcl` (migration control) и предназначена для детального учета и мониторинга процесса переноса объектов из Microsoft SQL Server в PostgreSQL. Система включает 26 специализированных таблиц с автоматическим контролем целостности данных.

### 🏗️ Архитектура системы

#### **Основные компоненты:**

**1. Управление задачами миграции:**
- `migration_tasks` - центральная таблица для учета задач миграции
- Автоматическое отслеживание дат создания и обновления

**2. Объекты Microsoft SQL Server:**
- `mssql_objects` - родительская таблица для всех объектов MS SQL
- `mssql_tables`, `mssql_views`, `mssql_functions`, `mssql_stored_procedures` - дочерние таблицы
- **Наследование PostgreSQL** для обеспечения иерархии объектов
- Связь с задачами миграции через `task_id`

**3. Объекты PostgreSQL:**
- `postgres_objects` - родительская таблица для всех объектов PostgreSQL
- `postgres_tables`, `postgres_views`, `postgres_functions`, `postgres_stored_procedures` - дочерние таблицы
- **Наследование PostgreSQL** для обеспечения иерархии объектов
- Связь с задачами миграции через `task_id`

**4. Система колонок:**
- `mssql_columns` - колонки таблиц MS SQL
- `postgres_columns` - колонки таблиц PostgreSQL
- Связи один-ко-многим между таблицами и колонками
- **Отсутствие прямой связи с задачами миграции** (согласно схеме)

**5. Система типов данных:**
- `mssql_data_types` - типы данных MS SQL с дочерними таблицами базовых и производных типов
- `postgres_data_types` - типы данных PostgreSQL с дочерними таблицами базовых и производных типов
- Связи один-ко-многим между типами и колонками
- Связи один-к-одному между соответствующими типами MS SQL и PostgreSQL

**6. Система управления проблемами миграции:**
- `migration_problems` - родительская таблица для всех проблем миграции
- `table_migration_problems`, `column_migration_problems` - дочерние таблицы для проблем таблиц и колонок
- `table_problem_solutions`, `column_problem_solutions` - способы решения проблем
- **Связь один-ко-многим**: одна проблема может иметь несколько способов решения

**7. Система связи объектов с проблемами:**
- `mssql_tables_problems_mapping` - связь таблиц MS SQL с способами решения проблем
- `mssql_columns_problems_mapping` - связь колонок MS SQL с способами решения проблем
- **Автоматический контроль уникальности** через триггеры PostgreSQL

### 🔧 Технические особенности

#### **Наследование PostgreSQL:**
```sql
-- Пример наследования для таблиц MS SQL
CREATE TABLE mcl.mssql_tables (...) INHERITS (mcl.mssql_objects);
CREATE TABLE mcl.mssql_views (...) INHERITS (mcl.mssql_objects);
CREATE TABLE mcl.mssql_functions (...) INHERITS (mcl.mssql_objects);
CREATE TABLE mcl.mssql_stored_procedures (...) INHERITS (mcl.mssql_objects);
```

#### **Автоматический контроль уникальности:**
```sql
-- Функция триггера для проверки уникальности таблица-проблема
CREATE OR REPLACE FUNCTION mcl.check_table_problem_uniqueness()
RETURNS TRIGGER AS $$
DECLARE
    v_problem_id INTEGER;
BEGIN
    -- Получаем problem_id из solution_id
    SELECT problem_id INTO v_problem_id 
    FROM table_problem_solutions 
    WHERE id = NEW.solution_id;
    
    -- Проверяем уникальность таблица-проблема
    IF EXISTS (
        SELECT 1 FROM mssql_tables_problems_mapping m
        JOIN table_problem_solutions s ON m.solution_id = s.id
        WHERE m.table_id = NEW.table_id 
        AND s.problem_id = v_problem_id
        AND m.id != COALESCE(NEW.id, 0)
    ) THEN
        RAISE EXCEPTION 'Таблица % уже имеет проблему %. Уникальность нарушена.', 
            NEW.table_id, v_problem_id;
    END IF;
    
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

### 📊 Порядок работы при выявлении проблемы

- **Автоматическое обнаружение** при попытке миграции объекта
- **Создание записи** в соответствующей таблице проблем (`table_migration_problems` или `column_migration_problems`)
- **Присвоение способа решения** "способ решения не определен" по умолчанию

#### **2. Создание записи связи:**
```sql
-- Пример создания связи таблица-проблема
INSERT INTO mcl.mssql_tables_problems_mapping 
(table_id, solution_id, solution_status, resolution_notes) 
VALUES 
(1, 1, 'active', 'Проблема с заглавными буквами в имени таблицы обнаружена');
```

#### **3. Работа с проблемой:**
- **Статус "активна"** - проблема выявлена, но не решена
- **Замена способа решения** на конкретный способ по мере определения
- **Обновление статуса** на "решена" при успешном решении

#### **4. Автоматический контроль:**
- **Триггер проверяет уникальность** таблица-проблема при каждой операции

- **Валидация связей** между объектами и способами решения
